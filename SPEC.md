## 1. Overview

There is no generation pipeline, no API key, no MCP and no Notion integration. The question bank is generated by **Claude Code itself**, using a project skill. The source is a **public, published Notion link**. The repo contains:

1. **`npm run fetch-notes`.** A small script that downloads the published page (no login) and saves it as Markdown in `source/notes.md`.
2. **The skill `quiz-bank`.** Claude reads `source/notes.md` and your **example questions**, splits the notes by book/chapter, writes and self-checks questions, and saves JSON files.
3. **The static quiz app.** It is hosted on GitHub Pages and reads those JSON files.

```
npm run fetch-notes   ──► source/notes.md   (public Notion link, no auth)
You in Claude Code: "/quiz-bank update"  (or "generate questions for <chapter>")
      │
      ├─ reads source/notes.md
      ├─ reads examples/ (YOUR historical questions, required) for style & difficulty
      ├─ writes app/public/data/bank/<book>/<chapter>.json + index.json
      └─ git commit & push ──► GitHub Actions ──► GitHub Pages
```

**Anti-"Quizlet problem" rule.** Each question stores several phrasings of the correct answer and many distractors. Each run shows 1 random correct phrasing, **3** random distractors, and a random stem phrasing, shuffled into **A–D**.

Upgrade path: if you later want automated or cheap bulk regeneration, the full pipeline (Node + Claude API) can be added. The JSON schema stays the same, so the app doesn't change.

## 2. Skill + Notion source

### 2.1 `fetch-notes` script (public link, no auth)
- `scripts/fetch-notes.ts`, run with `tsx`.
- Takes `notionUrl` from the config, e.g. `https://<workspace>.notion.site/<slug>-<pageId>`, and extracts the 32-hex page ID.
- Uses the unofficial `notion-client` package (`new NotionAPI().getPage(id)`), which reads published pages without a token.
- Walks the returned block tree in order and converts it to Markdown:
  - headings, paragraphs, bulleted/numbered lists, to-dos, quotes, callouts, code
  - toggles (include their children)
  - tables (as Markdown tables) and dividers
  - images as `[image: caption]`
  - child pages: recurse, and inline them under their title as a heading
- Writes `source/notes.md` and logs the number of headings and words.
- **Fallbacks, in order:**
  1. Claude's own WebFetch on the public link. Published Notion pages render with JavaScript, so this often returns little.
  2. The user exports the page (`⋯ → Export → Markdown & CSV`) and drops it into `source/`.
- **Commit `source/notes.md`.** This gives a diffable history of the notes, and `update` mode only regenerates changed chapters.

### 2.2 Config: `quiz.config.json`
```json
{
  "notionUrl": "<public published notion.site link>",
  "bookHeading": "h1",
  "chapterHeading": "h2",
  "language": "pl",
  "questionsPer1000Words": 5,
  "optionsShown": 4
}
```
Confirm with the user how books/chapters are marked (heading levels, "Rozdział N" text, or child pages).

### 2.3 Example questions (provided by the user, REQUIRED)
The user supplies real historical questions from the same classes. Generated questions must match them in **difficulty, detail level, phrasing style and question types**, e.g. definitions vs. applications, numeric details vs. concepts, negations like "which is NOT…".

- Location: `examples/`, one file per book (`examples/<bookId>.md`), or `examples/general.md` if not book-specific.
- Format is free-form, so the user can paste as-is. Preferred format:
  ```
  ## <chapter title or "?">
  Q: Treść pytania
  A) …  B) …  C) …  D) …
  Answer: B
  ```
  Questions without answers are fine. They still show style and difficulty.
- If `examples/` is empty, the skill must **stop and ask the user** for example questions before generating. It must not proceed with a generic style.
- Use the examples only for style and calibration. Never copy them. Never test facts that aren't in the notes.
- The skill writes a short `examples/STYLE.md` summary of the observed style: typical stem length, how detailed, share of numeric/definition/application questions, distractor style. The user reviews it once. All chapters then follow it, keeping difficulty consistent.

### 2.4 Question bank schema
```ts
Question = {
  id: string,              // stable slug: <bookId>-<chapterId>-<nn>
  bookId: string, chapterId: string,
  stems: string[],         // 1–3 phrasings of the same question
  correct: string[],       // 2–4 equivalent phrasings of the ONE correct answer (1 if not rephrasable)
  distractors: string[],   // 6–12 plausible, definitely-wrong options
  explanation: string,     // 1–3 sentences
  sourceExcerpt: string,   // short supporting excerpt from the notes
  difficulty: 1 | 2 | 3,
  status: "ok" | "flagged"
}
```
Files:
- `app/public/data/bank/<bookId>/<chapterId>.json`: `{ bookId, chapterId, chapterTitle, sourceHash, questions: Question[] }`
- `app/public/data/index.json`: `{ books: [{ id, title, chapters: [{ id, title, questionCount }] }] }`

Add a tiny `npm run check-bank` script (zod). It validates the schema, duplicate options, correct-vs-distractor overlap, and minimum counts. The skill runs it after each write.

## 3. Static app

### 3.1 Stack
- Vite + TypeScript (Svelte or vanilla), mobile-first.
- Loads `data/index.json`, then lazily loads only the selected chapter files.
- Deploy with GitHub Actions → GitHub Pages, with Vite `base` = repo name.

### 3.2 Flow
1. **Setup.** Books with expandable chapter checkboxes, "whole book", and per-chapter question counts. Pick a question count, capped at available. Remember the last selection in `localStorage`, wrapped in try/catch.
2. **Quiz.** One question per screen:
   - random stem from `stems`
   - 1 random answer from `correct`
   - 3 random from `distractors`
   - shuffle, label **A–D**
   - Tap to answer, then show correct/incorrect, `explanation`, and an expandable source (excerpt, book, chapter).
3. **Summary.** Score, per-chapter breakdown, list of misses, and a "retry missed" button (re-randomized).

### 3.3 Logic
- Sample questions without replacement across selected chapters.
- Skip `flagged` questions by default.
- Seeded RNG (mulberry32), with `?seed=` for reproducible runs.
- Optional: per-question miss stats in `localStorage` and a "focus on weak" mode.
- Keyboard shortcuts 1–4 / A–D, dark mode via `prefers-color-scheme`.

### 3.4 Tests (vitest)
- Option assembly always yields exactly 4 unique options with exactly 1 correct.
- The correct position is roughly uniform over 10k runs.

## 5. Milestones
- **M1 Setup.** App skeleton + check-bank + fetch-notes + skill installed.
- **M2 Source + style.**
  - Fetch the notes and run "outline" mode (books/chapters with word counts). The user confirms the split.
  - The user pastes example questions, the skill writes STYLE.md, and the user approves it.
- **M3 One chapter.** Generate it, review by hand, tune the skill's rules.
- **M4 Full bank + deploy.**
- **M5 Polish.** Retry missed, weak mode.

## 6. Notes
- The bank is public on a free GitHub Pages site.
- `notion-client` is unofficial and could break if Notion changes internals. The Markdown export is the zero-code fallback.
- Generation runs on your Claude subscription inside Claude Code, so there are no API costs. Large note sets may need several sessions; generate chapter by chapter.
